## 6.2 How `delivery_type` is resolved (the piece we fixed)

`delivery_type` is now resolved by **Discover Context**, not by sniffing an existing GP:

1. `GET /core/dynamic-screen/Gate%20Pass/` → find the `delivery_type` field in `screendefinition_set` → take `filter_dropdown_raw_query[0].id`.
2. Verified dropdown on tenant 795: **29 = Spot, 28 = Delivery** → first option = **29**.
3. Written to `pur_gp_delivery_type`, narrated in `pur_sniff_status` (`delivery_type 29 from GP schema`), and appended to `pur_ctx` as `gp.delivery_type`.
4. If the schema is unavailable, Discover notes it and Create GP falls back to default **29**.

Matches the Python chain: `ChainContextDiscoverer` resolves `delivery_type` the same way (`chain_context.py` → `_dropdown("Gate Pass", "delivery_type", ...)`).

**List GP is a pure read now** — it never sniffs; it exists for inspection only.

## 6.4 The `uom_conversion` fix (bug we corrected)

The old Create GP sent `pur_uom_conversion` (the item's real conversion — **20** on this tenant). The Python chain **hardcodes 1.0** in `_gp_items_from`, and every verified stored GP stores `1.0`. Sending 20 was a silent mismatch with the known-good chain — now fixed to `1.0`.

## 6.5 Test script (post-response)

```js
var id = data.id || data.entry_id;
if (!id) throw new Error('GP create failed: ' + pm.response.text());
pm.environment.set('pur_gp_id', id);
```

Stores `pur_gp_id` for GRN (`gate_pass_ref_id_id`).

> **Heads-up:** GRN consumes `pur_gp_id` via `gate_pass_ref_id_id` but uses the item's **real** `uom_conversion` (20 on 795), not GP's 1.0 — see `07-grn.md` §7.4. GP's `1.0` and GRN's real value are both correct.

## 6.6 Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| `Missing GP deps: pur_po_id, ...` | Run Create PO first (or a full Discover → PO sequence); check `pur_sniff_status` in the error. |
| `delivery_type 0` or NaN | GP schema unavailable + paused env race — re-run Discover; or set `pur_gp_delivery_type=29` manually. |
| GP create 4xx/5xx | Paste raw body from the console (`View → Show Postman Console`) into a formatter; most often a stale `pur_*` set or expired token (re-paste token in the env). |
| 401 on `/procure_to_pay/*` | Token no longer has access to this tenant; re-auth and set `tenant_id` to the tenant your token can reach (795 in this session). |
