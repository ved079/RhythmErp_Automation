PURPOSE
-------
This document is a reusable reference for creating entries in Rhythm ERP's
dynamic screens via direct API calls, completely bypassing the UI. It also
explains how to integrate this approach into an existing Selenium + Pytest
automation suite.

This approach was discovered and validated on the following screens:
  - Designation (simple: 2 text fields, 1 toggle)
  - Customer (complex: 3-tab stepper, 22 dropdowns, cascading address)
  - HSN SAC (medium: text + dropdown + toggle)
  - Error Code Mst (medium: text + dropdown + toggle)

The API approach turned a 15-minute UI struggle per 20 entries into a
10-second curl loop. Same result, 90x faster, zero flakiness.


================================================================================
SECTION 1: WHY API-FIRST?
================================================================================

The Problem with UI-Based Entry:
- Angular Material dropdowns (mat-select) are notoriously hard to automate
  with Selenium — they need click-wait-type-enter sequences, and even then
  they randomly fail to register the selection
- Cascading dropdowns (Country -> State -> District -> Taluka -> Village)
  require sequential waits between each selection
- Auto-population from "Party Reference" overwrites fields you already filled
- SweetAlert2 popups for validation failures are hard to detect/dismiss
- Each entry takes 30-60 seconds of careful UI interaction
- Flaky, brittle, and breaks on any UI change

The API Solution:
- Every dynamic screen in Rhythm ERP uses the SAME endpoint:
    POST /core/dynamic-screen-wrapper/
- Dropdowns are just integer FK IDs in the JSON payload
- No UI interaction needed — just HTTP POST with the right JSON
- 20 entries created in ~10 seconds with a curl loop
- Zero flakiness, deterministic, fast

SECTION 2: HOW IT WORKS — THE 6-STEP PROCESS
================================================================================

STEP 1: NAVIGATE TO THE SCREEN
-------------------------------
Open the target screen in the browser:
  URL format: https://rhythmerp.algorhythms.in/#/dynamic-screens/{ScreenName}
Example: https://rhythmerp.algorhythms.in/#/dynamic-screens/Designation

Click the "Add" button to open the creation form. This loads the form schema
and field definitions. Do NOT fill anything yet.


STEP 2: INSTALL XHR INTERCEPTORS
----------------------------------
Open the browser's Developer Tools (F12) -> Console tab. Paste this code:

```javascript
(function() {
    const origOpen = XMLHttpRequest.prototype.open;
    const origSend = XMLHttpRequest.prototype.send;
    const origSetHeader = XMLHttpRequest.prototype.setRequestHeader;

    XMLHttpRequest.prototype.open = function(method, url) {
        this._method = method;
        this._url = url;
        this._headers = {};
        return origOpen.apply(this, arguments);
    };

    XMLHttpRequest.prototype.setRequestHeader = function(key, value) {
        this._headers[key] = value;
        return origSetHeader.apply(this, arguments);
    };

    XMLHttpRequest.prototype.send = function(body) {
        if (this._url.includes('dynamic-screen-wrapper') && this._method === 'POST') {
            console.log('========== CAPTURED ==========');
            console.log('URL:', this._url);
            console.log('METHOD:', this._method);
            console.log('HEADERS:', JSON.stringify(this._headers, null, 2));
            console.log('PAYLOAD:', body);
            console.log('==============================');
        }
        return origSend.apply(this, arguments);
    };
})();
```

This interceptor will log every POST request to the dynamic-screen-wrapper
endpoint, including the full JSON payload and auth headers.


STEP 3: FILL THE FORM AND SUBMIT ONCE (MANUALLY)
--------------------------------------------------
Fill out the form with valid test data and click Submit/Save. The interceptor
will capture the exact payload format that the server expects.

Important notes for filling:
  - DO NOT select "Party Reference" dropdown — it auto-populates and
    overwrites fields you've already filled. Skip it entirely.
  - For dropdowns, just pick any valid option — we only need the FK ID format
  - Fill ALL required fields, otherwise the submission will fail with
    "Validation Failed" and you won't capture the payload
  - If submission succeeds, check the console for the CAPTURED output

What you'll see in the console:
  - URL: the full endpoint path
  - HEADERS: Authorization (Bearer token) + X-Tenant-ID + Content-Type
  - PAYLOAD: the complete JSON body

STEP 4: CAPTURE AUTH HEADERS
------------------------------
From the interceptor output, note down:

  1. Authorization header value: "Bearer eyJhbGciOiJIUzI1NiIs..."
  2. X-Tenant-ID header value: e.g., "599"

These are required for every API call. The Bearer token expires after some
time (likely 1-24 hours depending on server config), so re-capture if you
get 401 errors.

If using the Python client (see Section 4), the login() method handles
token capture automatically.


STEP 5: RESOLVE DROPDOWN FK IDs VIA GET CALLS
-----------------------------------------------
Each dropdown in the form loads its options from a GET endpoint. You can find
these endpoints by watching the Network tab while opening the form.

Common patterns:
  - GET /api/ownership-status/           -> list of ownership types
  - GET /api/sale-type/                  -> list of sale types
  - GET /api/country/                    -> list of countries
  - GET /api/state/?country=1            -> states for India (ID=1)
  - GET /api/district/?state=12          -> districts for Maharashtra
  - GET /api/taluka/?district=345        -> talukas for a district
  - GET /api/village/?taluka=678         -> villages for a taluka

You can also call these GET endpoints with your auth headers to get the full
list of options, then pick the IDs you need.

Curl example:
  curl -X GET "https://rhythmerp.algorhythms.in/api/country/" \
    -H "Authorization: Bearer <TOKEN>" \
    -H "X-Tenant-ID: 599" \
    -H "Content-Type: application/json"

This returns a JSON array like:
  [{"id": 1, "name": "India"}, {"id": 2, "name": "USA"}, ...]

For India specifically: country_id = 1 (verify this from the response)


STEP 6: BATCH CREATE VIA CURL OR PYTHON
-----------------------------------------
Now you have everything needed:
  - The exact payload format (from Step 3)
  - Auth headers (from Step 4)
  - Dropdown FK IDs (from Step 5)

Option A — Curl loop (quick one-liner for immediate use):

4.1 — API CLIENT MODULE
------------------------
Create a new file: api_client.py (or add to existing utilities)

```python
import requests
import time
import random
import string
from typing import List, Dict, Optional


class RhythmERPAPIClient:
    """
    Direct API client for Rhythm ERP dynamic screens.
    Bypasses the UI entirely for data creation.

    Usage:
        client = RhythmERPAPIClient()
        client.login()

        # Simple screen
        client.create_entry({
            "id": "", "name": "Manager", "status": True,
            "children": [], "attribute_name": "Designation"
        })

        # Complex screen with children
        client.create_entry({
            "id": "", "company_name": "Patil Agro",
            "attribute_name": "Customer",
            "children": [
                {"attribute_name": "Customer Details", "country": 1},
                {"attribute_name": "Customer Bank Details", "account_type": 1}
            ]
        })
    """

    BASE_URL = "https://rhythmerp.algorhythms.in"

    def __init__(self, username="user@admin.com", password="Tenant@123456789",
                 facility="tenant1"):
        self.username = username
        self.password = password
        self.facility = facility
        self.session = requests.Session()
        self.token = None
        self.tenant_id = None

    def login(self):
        """
        Authenticate and set Bearer token + X-Tenant-ID on the session.

        IMPORTANT: You may need to adjust the login endpoint and response
        parsing based on the actual ERP auth flow. To find the exact login
        endpoint, watch the Network tab when you login via the browser.

        Common login endpoints to try:
          - POST /api/auth/login/
          - POST /api/token/
          - POST /api/v1/auth/login/
        """
        # Attempt login
        login_resp = self.session.post(
            f"{self.BASE_URL}/api/auth/login/",
            json={
                "email": self.username,
                "password": self.password,
                "facility": self.facility
            }
        )
        login_resp.raise_for_status()
        data = login_resp.json()

        # Extract token — adjust key names based on actual response
        self.token = (
            data.get("access") or
            data.get("token") or
            data.get("key") or
            data.get("auth_token")
        )

        # Extract tenant ID — adjust based on actual response
        self.tenant_id = (
            data.get("tenant_id") or
            data.get("facility_id") or
            data.get("tenant")
        )

        if not self.token:
            raise ValueError(f"Could not extract token from login response: {data}")

        # Set session headers — all subsequent requests use these
        self.session.headers.update({
            "Authorization": f"Bearer {self.token}",
            "X-Tenant-ID": str(self.tenant_id) if self.tenant_id else "599",
            "Content-Type": "application/json"
        })

        print(f"[API] Logged in. Token: {self.token[:30]}... | Tenant: {self.tenant_id}")
        return self.token, self.tenant_id

    def login_from_browser(self, token, tenant_id):
        """
        Alternative: If you already have a token from browser interception,
        use this instead of login(). Useful when the login endpoint is
        unknown or uses a different auth flow.

        Args:
            token: Bearer token string (without "Bearer " prefix)
            tenant_id: X-Tenant-ID value (e.g., "599")
        """
        self.token = token
        self.tenant_id = tenant_id
        self.session.headers.update({
            "Authorization": f"Bearer {self.token}",
            "X-Tenant-ID": str(self.tenant_id),
            "Content-Type": "application/json"
        })
        print(f"[API] Session set from browser token. Tenant: {self.tenant_id}")

    def create_entry(self, payload: Dict) -> Optional[Dict]:
        """
        Create a single entry on any dynamic screen.

        Args:
            payload: Full JSON payload matching the captured format.
                     Must include "attribute_name" matching the screen.

        Returns:
            Response JSON on success, None on failure.
        """
        resp = self.session.post(
            f"{self.BASE_URL}/core/dynamic-screen-wrapper/",
            json=payload
        )

        if resp.status_code in (200, 201):
            name = payload.get("name") or payload.get("company_name") or "entry"
            print(f"  [OK] Created: {name}")
            return resp.json()
        else:
            name = payload.get("name") or payload.get("company_name") or "entry"
            print(f"  [FAIL] {name} — Status {resp.status_code}: {resp.text[:200]}")
            return None

    def batch_create(self, payloads: List[Dict], delay: float = 0.3) -> List[Optional[Dict]]:
        """
        Create multiple entries in sequence.

        Args:
            payloads: List of JSON payloads.
            delay: Seconds between requests (avoid rate limiting).

        Returns:
            List of response JSONs (None for failed entries).
        """
        results = []
        total = len(payloads)
        for i, payload in enumerate(payloads, 1):
            print(f"[{i}/{total}] Creating...")
            result = self.create_entry(payload)
            results.append(result)
            if delay and i < total:
                time.sleep(delay)
        success = sum(1 for r in results if r is not None)
        print(f"\n[DONE] {success}/{total} entries created successfully.")
        return results

    def get_options(self, endpoint_path: str) -> List[Dict]:
        """
        Fetch dropdown options from a GET endpoint.

        Args:
            endpoint_path: Full or relative path, e.g., "/api/country/"

        Returns:
            List of option dicts, e.g., [{"id": 1, "name": "India"}, ...]
        """
        if not endpoint_path.startswith("http"):
            url = f"{self.BASE_URL}{endpoint_path}"
        else:
            url = endpoint_path

        resp = self.session.get(url)
        resp.raise_for_status()
        return resp.json()

    def find_option_id(self, endpoint_path: str, name: str) -> Optional[int]:
        """
        Fetch options and find the ID for a specific name.

        Args:
            endpoint_path: GET endpoint for the dropdown.
            name: The option name to search for (case-insensitive).

        Returns:
            The integer ID, or None if not found.
        """
        options = self.get_options(endpoint_path)
        for opt in options:
            opt_name = opt.get("name", "").lower()
            if opt_name == name.lower():
                return opt["id"]
        print(f"  [WARN] Option '{name}' not found at {endpoint_path}")
        return None
```

def generate_random_pan() -> str:
    """Generate a random but valid-format PAN number: ABCDE1234F"""
    letters = string.ascii_uppercase
    return (
        "".join(random.choice(letters) for _ in range(5)) +
        "".join(str(random.randint(0, 9)) for _ in range(4)) +
        random.choice(letters)
    )


def generate_random_phone() -> str:
    """Generate a random 10-digit Indian phone number starting with 9/8/7/6."""
    return f"{random.choice('9876')}" + "".join(str(random.randint(0, 9)) for _ in range(9))

================================================================================
SECTION 5: TROUBLESHOOTING
================================================================================

PROBLEM: 401 Unauthorized
SOLUTION: Token expired. Re-login via the API client or re-capture from
          browser. Tokens typically last 1-24 hours.

PROBLEM: 400 Bad Request with "Validation Failed"
SOLUTION: Missing required field in payload. Compare your payload against
          a captured successful submission. Check that all required fields
          are present and dropdown FK IDs are valid integers.

PROBLEM: Dropdown returns empty list
SOLUTION: The FK ID might be wrong, or the cascading parent isn't set.
          For cascading dropdowns (Country -> State -> District -> etc.),
          always query with the parent filter, e.g.:
            GET /api/state/?country=1    (1 = India)
            GET /api/district/?state=12  (12 = Maharashtra)

PROBLEM: "Party Reference" auto-populates and overwrites fields
SOLUTION: Simply don't include "party_reference" in the payload. If the
          field exists in the form but you skip it, the server accepts
          the submission without it (it's not required).

PROBLEM: Payload format is different from expected
SOLUTION: Re-capture the payload by filling the form once in the browser
          with the XHR interceptor installed. The API may have been
          updated since this document was written.

PROBLEM: Need to find the login endpoint
SOLUTION: Open the ERP login page in the browser, open Network tab,
          submit the login form, and look for the POST request that
          returns a token. That's your login endpoint.
